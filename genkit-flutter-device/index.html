En este codelab vas a construir QueComerIA: le tomas una foto a tu nevera y la app te muestra un tablero con los alimentos que vio, para que los corrijas, y después las recetas que puedes cocinar. Todo corre con GenKit dentro de la app: sin un servidor propio, con un modelo que funciona sin conexión en el dispositivo y con Gemini en la nube cuando conviene.

Lo que vas a construir

                                    ┌─▶ Gemma 4 E2B (en el dispositivo, sin red)
 App Flutter ──▶ GenKit ──▶ router ─┤
                                    └─▶ Gemini (Firebase AI Logic, en la nube)

Cada pregunta pasa por un router que decide dónde se responde:

La regla de este codelab

El modelo ve y presenta. Tu código decide qué receta sirve y qué falta comprar.

Un modelo puede inventar que "con eso te alcanza para una lasaña". Aquí el modelo lee la foto y arma la pantalla, pero la comparación entre tus ingredientes y las recetas la hace una función de Dart que puedes probar con flutter test.

Lo que vas a aprender

  • Correr un modelo en el dispositivo con GenKit y genkit_flutter_edge_ai (Gemma 4 E2B).
  • Usar tools que se ejecutan dentro de la app, también sin red.
  • Hacer búsqueda semántica offline con embeddings en el dispositivo (EmbeddingGemma 2).
  • Llamar a Gemini desde la app con Firebase AI Logic (genkit_firebase_ai), sin guardar una API key.
  • Decidir en cada pregunta entre el dispositivo y la nube con genkit_hybrid.
  • Leer una foto con el modelo del dispositivo, sin que salga del teléfono.
  • Responder con un tablero editable y tarjetas (A2UI) generadas en el dispositivo o en la nube.

Lo que necesitas

  • Dart SDK 3.13.0 o superior y Flutter 3.47.0 o superior.
  • Un dispositivo que corra el modelo: un Mac con Apple Silicon (macOS 15 o superior), o un teléfono Android o un iPhone físico reciente.
  • Unos 3 GB libres para los modelos.
  • Un proyecto de Firebase y la CLI de FlutterFire.

Los modelos pesan unos 2,7 GB en total. Si estás en un taller, descárgalos antes, con buena conexión: hacerlo al mismo tiempo que el resto de asistentes puede tardar mucho.

Esto es un ejemplo educativo. Las recetas son ocho de muestra y el modelo puede equivocarse al identificar alimentos. No uses esta app para decidir si un alimento está en buen estado o si es seguro para una alergia.

genkit_flutter_edge_ai y flutter_edge_ai son paquetes de la comunidad (no del equipo de GenKit) y cambian rápido. Fija las versiones en tu pubspec.yaml.

flutter_edge_ai trae un catálogo con los modelos y sus URLs fijas. El plugin no descarga los modelos: es responsabilidad de la app.

import 'package:flutter_edge_ai/flutter_edge_ai.dart';
import 'package:flutter_edge_ai_litertlm/flutter_edge_ai_litertlm.dart';

/// Gemma 4 E2B: el modelo que genera las respuestas en el dispositivo.
final gemma = LiteRtLmModels.gemma4E2bIt.generic;

/// EmbeddingGemma 2 (solo texto): convierte textos en vectores para buscar.
final embeddingGemma = LiteRtEmbedders.embeddinggemma2Text270m.generic;

/// Descarga e instala los dos modelos. Si ya están instalados, no los baja de nuevo.
Future<void> installModels(void Function(String status) onStatus) async {
  await FlutterEdgeAi.installModelFromCatalog(gemma)
      .withProgress((p) => onStatus('Gemma 4 E2B: $p%'))
      .install();

  await FlutterEdgeAi.installEmbedder()
      .modelFromNetwork(embeddingGemma.model.url)
      .withProgress((p) => onStatus('EmbeddingGemma 2: $p%'))
      .install();

  onStatus('Modelos listos');
}

Los modelos se instalan una sola vez y sobreviven a reinicios de la app. La segunda vez que llames a installModels, no se vuelven a descargar.

/// Minúsculas y sin tildes: 'Huevos ' y 'huévos' son lo mismo.
String normalize(String text) {
  const from = 'áéíóúüñ';
  const to = 'aeiouun';
  final lower = text.trim().toLowerCase();
  return [
    for (final c in lower.split('')) from.contains(c) ? to[from.indexOf(c)] : c,
  ].join();
}

/// Singular y plural simples: 'huevo' ~ 'huevos', 'tomates' ~ 'tomate'.
Set<String> _variants(String name) {
  final n = normalize(name);
  return {
    n,
    if (n.endsWith('es') && n.length > 3) n.substring(0, n.length - 2),
    if (n.endsWith('s') && n.length > 2) n.substring(0, n.length - 1),
  };
}

Set<String> _pantryForms(List<String> pantry) => {
  for (final item in pantry) ..._variants(item),
};

bool _has(String ingredient, Set<String> forms) =>
    _variants(ingredient).intersection(forms).isNotEmpty;

/// Las recetas a las que les falta menos. Ignora las que no tienen ni un
/// ingrediente de la despensa.
List<Map<String, Object>> matchRecipes(List<String> pantry, {int limit = 3}) {
  final forms = _pantryForms(pantry);
  final scored = [
    for (final r in recipes)
      (
        recipe: r,
        have: [
          for (final i in r.ingredients)
            if (_has(i, forms)) i,
        ],
        missing: [
          for (final i in r.ingredients)
            if (!_has(i, forms)) i,
        ],
      ),
  ].where((s) => s.have.isNotEmpty).toList();

  scored.sort((a, b) {
    final byMissing = a.missing.length.compareTo(b.missing.length);
    if (byMissing != 0) return byMissing;
    final byHave = b.have.length.compareTo(a.have.length);
    if (byHave != 0) return byHave;
    return a.recipe.name.compareTo(b.recipe.name);
  });

  return [
    for (final s in scored.take(limit))
      {
        'id': s.recipe.id,
        'name': s.recipe.name,
        'minutes': s.recipe.minutes,
        'have': s.have,
        'missing': s.missing,
      },
  ];
}

/// Lo que falta para cocinar las recetas elegidas, sin repetir.
///
/// Lanza un [ArgumentError] si un id no existe.
({List<String> recipes, List<String> items}) shoppingList(
  List<String> recipeIds,
  List<String> pantry,
) {
  final forms = _pantryForms(pantry);
  final names = <String>[];
  final items = <String>[];

  for (final id in recipeIds) {
    final recipe = recipes.where((r) => r.id == id).firstOrNull;
    if (recipe == null) throw ArgumentError('Receta desconocida: $id');

    names.add(recipe.name);
    for (final i in recipe.ingredients) {
      if (!_has(i, forms) && !items.contains(i)) items.add(i);
    }
  }
  return (recipes: names, items: items);
}

La comparación es literal (más singular y plural, y sin tildes): "queso mozzarella" no cuenta como "queso". Es una limitación a propósito, para que el código sea corto y se pueda probar. En una app real usarías una tabla de sinónimos.

Una receta no sabe qué ingredientes "tienes": eso solo existe como resultado de matchRecipes. Así el modelo nunca puede decir "ya tienes todo" por su cuenta.

matchRecipes y shoppingList son funciones normales de Dart: puedes probarlas con flutter test, sin el modelo.

lib/quecomeria_ai.dart

El mismo GenKit que usarías en un servidor, pero con el plugin de flutter_edge_ai: el modelo corre en el dispositivo. La tool findRecipes llama a tu matchRecipes y también corre en la app, así que todo funciona sin red.

import 'dart:math' as math;

import 'package:genkit/genkit.dart';
import 'package:genkit_flutter_edge_ai/genkit_flutter_edge_ai.dart';

import 'models.dart';
import 'recipes.dart';

const _system = '''
Eres QueComerIA, una asistente de cocina. Responde en español y en pocas frases.
- Si te dicen qué ingredientes tienen, llama una vez a findRecipes con esa lista.
Recomienda solo recetas que devuelvan las tools y di qué falta en cada una.''';

const _maxItems = 40;
const _maxName = 40;

/// Gemma en el dispositivo: en la GPU (si no hay, usa la CPU) y con
/// temperature 0, para que responda igual a la misma pregunta.
final _localModel = modelRef(
  '${GenkitFlutterEdgeAiPlugin.prefix}/gemma',
  customOptions: FlutterEdgeAiModelOptions.$schema,
  config: FlutterEdgeAiModelOptions(preferredBackend: 'gpu', temperature: 0),
);

/// Lo que el usuario marca en la pantalla. Las usarás en el router.
bool isOffline = false;
bool isPrivate = false;

class QueComerIA {
  QueComerIA._(this._ai);

  final Genkit _ai;

  /// La despensa que confirmó el usuario. La deja findRecipes.
  List<String> pantry = [];

  static Future<QueComerIA> create() async {
    // GenKit en el dispositivo: el plugin de flutter_edge_ai.
    final ai = Genkit(
      plugins: [
        GenkitFlutterEdgeAiPlugin(
          models: [
            FlutterEdgeAiModelConfig(name: 'gemma', modelType: gemma.modelType),
          ],
        ),
      ],
    );

    final quecomeria = QueComerIA._(ai);
    quecomeria._defineTools();

    return quecomeria;
  }

  void _defineTools() {
    _ai.defineTool(
      name: 'findRecipes',
      description:
          'Busca recetas con los ingredientes que el usuario confirmó. '
          'Devuelve las recetas ordenadas por lo que menos falta.',
      inputSchema: .list(.string(), description: 'Los ingredientes'),
      fn: (ingredients, _) async {
        // No confíes en lo que manda el modelo: recorta nombres y cantidad.
        pantry = [
          for (final i in ingredients)
            if (i.trim().isNotEmpty)
              i.trim().substring(0, math.min(i.trim().length, _maxName)),
        ].take(_maxItems).toList();
        return .response(matchRecipes(pantry));
      },
    );
  }

  /// Pregunta a QueComerIA. Devuelve la respuesta y dónde se generó.
  Future<({String text, String target})> ask(String question) async {
    final result = await _ai.generate(
      model: _localModel,
      system: _system,
      prompt: question,
      toolNames: ['findRecipes'],
    );

    // En GenKit 1.0, generate() no lanza si falla: revisa finishReason.
    final reason = result.finishReason;
    if (reason != .stop && reason != .length && reason != .unknown) {
      throw result.cause ?? StateError(result.finishMessage ?? '$reason');
    }
    return (text: result.text, target: 'onDevice');
  }
}

flutter run -d macos --dart-define=APP_CHECK_DEBUG_TOKEN=$APP_CHECK_DEBUG_TOKEN

Pulsa Preparar modelos (la primera vez se descargan) y escribe "Tengo huevos, tomate y cebolla". La primera respuesta tarda un poco más: el modelo se carga en memoria.

Qué pasó: es el mismo ai.generate() de GenKit, con otro plugin y _localModel como modelo. El modelo decidió llamar a findRecipes, tu código comparó los ingredientes con el recetario y Gemma escribió la respuesta con ese resultado, todo en el dispositivo.

La tool no confía en el modelo: recorta los nombres a 40 caracteres y la lista a 40 elementos. Y guarda la despensa en pantry, porque la vas a necesitar en el reto del final.

_localModel es una referencia al modelo con su configuración. preferredBackend: 'gpu' lo corre en la GPU: en un Mac, la primera respuesta pasa de unos 2 minutos en la CPU a unos 10 segundos. Si el dispositivo no tiene una GPU compatible, usa la CPU. temperature: 0 hace que responda igual a la misma pregunta, mejor para un modelo pequeño que tiene que llamar tools.

En GenKit 1.0, generate() no lanza cuando falla: devuelve un resultado con finishReason: failed y el error en cause. Por eso ask revisa finishReason antes de mostrar el texto.

findRecipes necesita ingredientes, pero a veces el usuario pide otra cosa: "algo fresco para un día de calor". Con embeddings puedes buscar por significado: cada receta se convierte en un vector, la pregunta también, y las más parecidas ganan. EmbeddingGemma 2 lo hace en el dispositivo, sin red.

class QueComerIA {
  // El código anterior...

  /// Convierte cada descripción en un vector una sola vez, al iniciar.
  Future<void> _buildIndex() async {
    final vectors = await _ai.embed(
      embedder: flutterEdgeAi.embedder('embedding-gemma'),
      documents: [
        for (final r in recipes)
          DocumentData(
            content: [TextPart(text: '${r.name}. ${r.description}')],
          ),
      ],
      options: FlutterEdgeAiEmbedConfig(taskType: 'retrievalDocument'),
    );

    for (var i = 0; i < recipes.length; i++) {
      _index.add((recipes[i], vectors[i].embedding));
    }
  }

  /// Búsqueda semántica: las 3 recetas más parecidas a la consulta.
  Future<List<Map<String, Object>>> semanticSearch(String query) async {
    final [queryVector] = await _ai.embed(
      embedder: flutterEdgeAi.embedder('embedding-gemma'),
      documents: [
        DocumentData(content: [TextPart(text: query)]),
      ],
    );

    final ranked = [..._index]
      ..sort((a, b) {
        return _cosine(
          b.$2,
          queryVector.embedding,
        ).compareTo(_cosine(a.$2, queryVector.embedding));
      });

    return [
      for (final (r, _) in ranked.take(3))
        {'id': r.id, 'name': r.name, 'minutes': r.minutes},
    ];
  }
}

double _cosine(List<double> a, List<double> b) {
  var dot = 0.0, na = 0.0, nb = 0.0;

  for (var i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    na += a[i] * a[i];
    nb += b[i] * b[i];
  }
  return dot / (math.sqrt(na) * math.sqrt(nb));
}

Future<({String text, String target})> ask(
  String question, {

    question = 'Tengo: ${seen.text.split('\n').join(', ')}';

Hasta aquí Gemma mira la foto y busca recetas con lo que vio. Pero un modelo pequeño se equivoca: confunde un limón con una naranja o ve leche donde hay yogur. Con A2UI la app responde con interfaz: un tablero con una casilla por alimento y un campo para lo que el modelo no vio, para que tú confirmes antes de buscar, y después una tarjeta por receta.

El modelo escribe la interfaz en A2UI Express, una notación compacta, y el middleware a2ui() de genkit_a2ui la valida y la convierte en mensajes JSON que la app dibuja con a2ui_flutter. El middleware corre en el GenKit de la app, así que funciona tanto con Gemma en el dispositivo como con Gemini en la nube.

Ojo con el contexto del modelo del dispositivo. a2ui() le enseña al modelo A2UI Express y los componentes del catálogo. Con el catálogo básico completo eso son unos 5.700 tokens. Por eso aquí usas un catálogo reducido (Column, Text, Button, CheckBox y tu RecipeCard, unos 2.500 tokens), que cabe en la ventana de 4.096.

Con A2UI cambia el reparto del trabajo. Las instrucciones de A2UI hacen el prompt mucho más largo, y con un prompt así un modelo de 2B pierde el resultado de las tools: llama a findRecipes, no ve lo que devolvió y la vuelve a llamar.

Cambia _ask: ahora recibe qué método de QueComerIA llamar, empieza un tablero nuevo (salvo que se lo pidas) y aplica los mensajes A2UI de la respuesta:

/// Llama a QueComerIA con [request] y aplica los mensajes A2UI que vuelven.
Future<void> _ask(
  Future<Reply> Function(QueComerIA quecomeria) request, {
  bool newBoard = true,
}) async {
  final quecomeria = _quecomeria;
  if (quecomeria == null || _busy) return;

  setState(() {
    _busy = true;
    _answer = '';
    _target = '';

    if (newBoard) _newBoard();
  });

  try {
    final reply = await request(quecomeria);
    for (final message in reply.ui) {
      try {
        _processor!.processMessages(message);
      } on A2uiError catch (e) {
        debugPrint('Mensaje A2UI inválido: ${e.message}');
      }
    }

    setState(() {
      _answer = reply.text;
      _target = reply.target == 'onDevice'
          ? '📱 En el dispositivo'
          : '☁️ En la nube';
    });
  } catch (e) {
    setState(() => _answer = 'Error: $e');
  } finally {
    setState(() => _busy = false);
  }
}

Dos capas de validación

Todo lo que llega a la pantalla, lo escriba el modelo o tu código, pasa por dos filtros, y ninguno confía en el otro:

Capa

Qué revisa

Si falla

1. a2ui() en GenKit

Que el Express compile, que cada componente y propiedad exista en el catálogo que ve el modelo y que respete sus guardas

Le pide al modelo una reparación. Si tampoco sirve, descarta el bloque

2. MessageProcessor

Otra vez, contra el catálogo de la app: componentes, schemas, guardas, raíz, referencias, profundidad y tipos de mensaje

Como las dos capas usan las mismas listas (onlyInColumn, onlyText en board_catalog.dart), no se pueden desincronizar: lo que GenKit deja pasar, la app lo sabe dibujar. Si una capa rechaza algo, verás UNALLOWED_PARENT o UNALLOWED_CHILD en el error.

El prompt de a2ui() no le cuenta las guardas al modelo: solo las revisa. Por eso la descripción de RecipeCard dice "Va dentro de un Column". Si una guarda rechaza seguido lo que escribe el modelo, díselo en la descripción o en el ejemplo del system.

La primera capa cuida qué puede pedir el modelo. La segunda, qué sabe dibujar la app. Aquí las dos corren en el teléfono, pero si mañana los mensajes llegan de un servidor (con remoteAgent, por ejemplo), la segunda sigue protegiendo la pantalla sin cambiar nada.

No uses ValidationConfig.relaxed para respuestas completas: acepta componentes que el catálogo no declara (allowUnknownElements) sin revisar su schema. Es para superficies que llegan en varios pedazos. En QueComerIA cada respuesta trae su superficie entera, así que va la estricta.

Antes de llevar algo así a producción, ten en cuenta:

  • El texto dentro de la foto no es una instrucción. Una nota pegada en la nevera puede decir "ignora tus instrucciones". No hay una defensa perfecta, pero sí capas: el system lo advierte, el modelo solo puede usar los componentes de tu catálogo, tu código recorta lo que llega del tablero y la app filtra las casillas por su cuenta.
  • La foto es privada. En QueComerIA nunca sale del teléfono. Si algún día la mandas a la nube, dilo claro antes de pedirla.
  • El prompt y tu código viajan dentro de la app. Cualquiera que desempaquete la app puede leerlos. No pongas ahí nada que deba ser secreto.
  • App Check en producción: cambia los proveedores de debug por los de atestación de cada plataforma (Play Integrity, App Attest).
  • La telemetría puede sacar del dispositivo lo que debía quedarse. El trazado de GenKit guarda el prompt completo, foto incluida; si exportas trazas, desactiva la captura de contenido para que "procesado en el dispositivo" siga siendo cierto.
  • Memoria y contexto: un modelo en el dispositivo tiene una ventana de contexto pequeña. Para conversaciones largas, usa el middleware trimContext() de genkit_flutter_edge_ai.
  • El tamaño importa: no empaquetes el modelo en la app; descárgalo bajo demanda y muestra el progreso, como hiciste.
  • Desinstalar no lo borra todo: al cargar un modelo en la GPU, el motor guarda cachés junto a él (archivos <modelo>_..._cache.bin y .xnnpack_cache en la carpeta de soporte de la app). Con Gemma 4 E2B pesan casi 1,8 GB, y FlutterEdgeAi.uninstallModel() no las borra. Si tu app cambia o desinstala un modelo, borra también sus cachés.
