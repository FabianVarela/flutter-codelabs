En este codelab vas a construir ViajarIA, el asistente de viajes de una agencia digital, usando GenKit Dart 1.0 (GA desde el 7 de octubre de 2026).

Vas a empezar con un servidor Dart mínimo y terminar con una app Flutter que conversa con un agente, muestra interfaz generada por él (A2UI) y le pide confirmación al usuario antes de actuar (interrupts).

Lo que vas a construir

 App Flutter ──HTTP──▶ Servidor Dart (Genkit) ──▶ Gemini (u otro proveedor)
                              │
                              └─ tools / flows / agente

Lo que vas a aprender

  • Usar generate() y salida estructurada con schemas (schemantic).
  • Definir flows y tools con tipos.
  • Mover el prompt de un flow a un archivo .prompt con Dotprompt.
  • Probar con el Developer UI.
  • Servir todo por HTTP con GenkitRouter.
  • Crear un agente y usarlo desde Flutter con remoteAgent.
  • Aplicar middleware: retry() y uno propio.
  • Hacer que el agente responda con interfaz (A2UI), con un catálogo propio en JSON.
  • Pausar una tool con un interrupt para pedir confirmación al usuario.

Lo que necesitas

  • Dart SDK 3.13.0 o superior y Flutter 3.47.0 o superior.
  • Una API key de Gemini (Google AI Studio).
  • Node.js (para el GenKit CLI).
  • Un editor y una terminal.

La Agents API (defineAgent, remoteAgent, stores, interrupts) sigue siendo experimental dentro de GenKit Dart 1.0: vive en package:genkit/experimental.dart y la documentación la llama Beta. El resto (flows, tools, schemas, middleware, HTTP) es estable.

Todo el código de este codelab sale de la documentación oficial de genkit.dev y de los paquetes publicados en pub.dev, adaptado a una agencia de viajes.

Qué pasó: Genkit(plugins: [...]) crea la instancia, googleAI() registra el plugin y ai.generate() llama al modelo. Cambiar de proveedor es cambiar el plugin y el modelo; el resto del código no se toca.

Para que el modelo responda con una estructura y no con texto libre, usas schemantic. Declaras clases abstractas con @Schema() y GenKit genera el resto.

bin/server.dart (reemplaza los imports y agrega arriba de main)

Los dos primeros imports ya los tienes; el nuevo es el de schemantic. Debajo de ellos van el part y los schemas:

import 'package:genkit/genkit.dart';
import 'package:genkit_google_genai/genkit_google_genai.dart';
import 'package:schemantic/schemantic.dart';

part 'server.g.dart';

// Lo que recibe el flow
@Schema()
abstract class $RecommendInput {
  String get topic;
}

// Lo que devuelve el flow
@Schema()
abstract class $TripRecommendation {
  String get destination;

  String get country;

  String get reason;
}

// Lo que recibe la tool
@Schema()
abstract class $SearchDestinationsInput {
  String get query;

  String? get type;

  int? get limit;
}

Reglas: la clase es abstracta, su nombre lleva el prefijo $ y los campos son getters.

Genera el código:

dart run build_runner build

Esto crea bin/server.g.dart con las clases RecommendInput, TripRecommendation y SearchDestinationsInput (sin el $). Cada una trae .$schema, toJson() y fromJson().

Si cambias los campos de un schema, vuelve a correr build_runner. Con GenKit 1.0 hay que regenerar los archivos .g.dart.

Un flow es una función con entrada y salida tipadas, observable y desplegable como endpoint. Su prompt lo vamos a guardar en un archivo .prompt con Dotprompt, en vez de escribirlo como un string en el código.

Dotprompt guarda cada prompt en un archivo: un encabezado YAML (modelo, entrada, salida) y una plantilla Handlebars. Así puedes cambiar la redacción sin tocar el código, y alguien que no programa puede revisarla.

prompts/recommend.prompt

Por defecto GenKit carga los .prompt de ./prompts, relativa a donde ejecutas el servidor. Crea la carpeta y el archivo. La entrada y la salida se describen con Picoschema, una forma compacta de escribir el esquema:

mkdir prompts

---
model: googleai/gemini-flash-latest
input:
  schema:
    topic: string, qué busca el usuario (playa, montaña, cultura...)
output:
  format: json
  schema:
    destination: string
    country: string
    reason: string, por qué se lo recomiendas
---
{{role "system"}}
Eres ViajarIA, la asistente de viajes de una agencia digital. Recomienda destinos reales y responde en español.

{{role "user"}}
Recomienda un destino de viaje para "{{topic}}".

En Picoschema la descripción va después de una coma: topic: string, la descripción. Escribir topic(la descripción): string es inválido: ese paréntesis es solo para el tipo (array, object, enum).

bin/server.dart (dentro de main)

Carga el prompt y úsalo dentro del flow. Como el archivo no tiene tipo de Dart, pásale outputParserSchema para que la salida llegue como TripRecommendation:

Future<void> main() async {
  final ai = Genkit(plugins: [googleAI()]);

  // -> prompts/recommend.prompt
  final recommendPrompt = await ai.prompt(
    'recommend',
    outputParserSchema: TripRecommendation.$schema,
  );

  final recommendFlow = ai.defineFlow(
    name: 'recommendTrip',
    inputSchema: RecommendInput.$schema,
    outputSchema: TripRecommendation.$schema,
    fn: (input, _) async {
      // La entrada es el mapa con las variables de la plantilla.
      final response = await recommendPrompt({'topic': input.topic});

      if (response.output == null) {
        throw Exception('La respuesta no cumple el schema.');
      }
      return response.output!;
    },
  );

  final rec = await recommendFlow(RecommendInput(topic: 'playa'));
  print('${rec.destination} — ${rec.country}: ${rec.reason}');
}

dart run bin/server.dart

Un flow se llama como una función: await recommendFlow(RecommendInput(...)). El compilador te dice qué campos tiene la respuesta.

outputParserSchema no se envía al modelo: el que se envía es el output.schema del archivo. Solo le dice a Dart a qué tipo convertir la respuesta.

Un archivo recommend.breve.prompt sería una variante del mismo prompt, y la cargas con ai.prompt('recommend', variant: 'breve', ...). Te sirve para comparar redacciones sin duplicar código.

Como se leen desde disco, la carpeta prompts/ tiene que viajar con tu servidor cuando lo despliegues.

Una tool es una función que el modelo puede decidir llamar. Por ahora usa un catálogo fijo.

  {'name': 'Parque Tayrona', 'country': 'Colombia', 'type': 'playa'},
  {'name': 'Cusco', 'country': 'Perú', 'type': 'cultura'},
  {'name': 'Ciudad de México', 'country': 'México', 'type': 'gastronomía'},
  {'name': 'Lisboa', 'country': 'Portugal', 'type': 'ciudad histórica'},
];

bin/server.dart (dentro de main, después de crear ai)

Future<void> main() async {
  // El código anterior...

  final searchDestinations = ai.defineTool(
    name: 'searchDestinations',
    description: 'Busca destinos del catálogo por nombre, país o tipo.',
    inputSchema: SearchDestinationsInput.$schema,
    fn: (input, _) async {
      final q = input.query.toLowerCase();
      final results = catalog
          .where((b) {
            return (b['name']!.toLowerCase().contains(q) ||
                    b['country']!.toLowerCase().contains(q)) &&
                (input.type == null || b['type'] == input.type);
          })
          .take(input.limit ?? 5)
          .toList();

      // Una tool devuelve un ToolResult: .response(...) con el resultado.
      return .response(results);
    },
  );

  // Pruébala pidiéndole al modelo que la use.
  final response = await ai.generate(
    model: googleAI.gemini('gemini-flash-latest'),
    prompt: '¿Tienen algo en Perú?',
    toolNames: ['searchDestinations'],
  );
  print(response.text);
}

Nota que el modelo decide cuándo llamar la tool y con qué argumentos. Tú solo la describes bien (description y los campos del schema).

Una tool también puede devolver .interrupt() para pausar la conversación. Lo usamos al final del codelab.

Si alguna vez no se imprime nada, ejecútalo de nuevo: de vez en cuando el modelo devuelve una respuesta vacía. Es una variación del modelo, no un error de tu código.

Un agente empaqueta el historial de la conversación, el bucle de tools, el streaming y la persistencia de sesión.

Experimental. Los imports de experimental.dart te darán un warning experimental_member_use del analyzer. Es esperado.

bin/server.dart (imports nuevos)

import 'package:genkit/experimental.dart'; // defineAgent, InMemorySessionStore
import 'package:genkit/experimental_io.dart'; // addAgent

bin/server.dart (antes de crear el router)

Un middleware envuelve cada llamada al modelo para agregar comportamiento sin tocar tu lógica. Se declara en la lista use: [...]. El primero que usamos viene en el core: retry(), que reintenta si falla la llamada al modelo.

Future<void> main() async {
  // El código anterior...

  final agent = ai.defineAgent(
    name: 'viajaria',
    model: googleAI.gemini('gemini-flash-latest'),
    system:
        'Eres ViajarIA, la asistente de viajes de una agencia digital. '
        'Ayudas a buscar destinos con la tool searchDestinations. Responde en español.',
    tools: [searchDestinations],
    // middleware: reintenta si falla el modelo
    use: [retry(maxRetries: 2)],
    // guarda las sesiones en memoria
    store: InMemorySessionStore(),
  );

  final genkit = GenkitRouter()
    ..addAction(recommendFlow)
    ..addAgent(agent, path: '/api/viajaria');

  // El código anterior...
}

addAgent monta la ruta del turno (POST /api/viajaria) y, como el agente tiene un store, también /getSnapshot y /abort cuando corresponde.

InMemorySessionStore es solo para pruebas: se pierde al reiniciar y no sirve con varias instancias. Para desarrollo local hay FileSessionStore('.sessions').

retry() también sirve en una llamada suelta (ai.generate(..., use: [retry(maxRetries: 2)])) y en el encabezado de un .prompt. Más adelante vas a escribir un middleware propio.

import 'package:genkit/experimental_client.dart'; // remoteAgent (browser-safe)
import 'package:material_ui/material_ui.dart';

// Android emulator: 10.0.2.2 apunta al localhost de tu máquina.
// iOS simulator / web / desktop: http://localhost:8080
const baseUrl = 'http://10.0.2.2:8080';

void main() => runApp(const MaterialApp(home: ViajarIAChat()));

class ViajarIAChat extends StatefulWidget {
  const ViajarIAChat({super.key});

  @override
  State<ViajarIAChat> createState() => _ViajarIAChatState();
}

class _ViajarIAChatState extends State<ViajarIAChat> {
  // Solo `url` es obligatorio. getSnapshotUrl y abortUrl son opcionales
  // (por defecto: $url/getSnapshot y $url/abort).
  late final _agent = remoteAgent(url: '$baseUrl/api/viajaria');
  late final _chat = _agent.chat(); // el chat conserva la conversación

  final _controller = TextEditingController();
  String _answer = '';
  bool _busy = false;

  @override
  void dispose() {
    _agent.close();
    _controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => Scaffold(
    appBar: AppBar(title: const Text('ViajarIA')),
    body: Padding(
      padding: const EdgeInsets.all(16),
      child: Column(
        children: [
          Expanded(child: SingleChildScrollView(child: Text(_answer))),
          TextField(
            controller: _controller,
            decoration: const InputDecoration(
              hintText: 'Pregunta por un destino',
            ),
            onSubmitted: (_) => _send(),
          ),
        ],
      ),
    ),
  );

  Future<void> _send() async {
    final text = _controller.text.trim();
    if (text.isEmpty || _busy) return;

    setState(() {
      _busy = true;
      _answer = '';
    });

    final turn = _chat.sendStream(text: text);
    await for (final chunk in turn.stream) {
      setState(() => _answer += chunk.text); // chunk.text = solo este fragmento
    }

    await turn.response; // resultado final del turno
    setState(() => _busy = false);
  }
}

En la siguiente sección el agente va a responder con interfaz usando A2UI, y la app la va a dibujar con a2ui_flutter. Este paquete trae una implementación de los componentes básicos (texto, tarjetas, botones, campos de formulario...), pero la hace con package:flutter/material.dart, y tu app usa material_ui. Los componentes de entrada de datos (TextField, CheckBox, Slider, ChoicePicker y DateTimeInput) necesitan widgets de ese Material y fallan dentro de tu app.

La solución es escribir tus propias versiones de esos cinco componentes con material_ui. Cada una es un ComponentImplementation: un name, un schema y un builder. El builder lee las propiedades con props y, cuando el usuario edita, escribe el valor en el modelo de datos con props.writable('value')?.set(...).

El catálogo es un contrato: dice qué componentes existen y qué propiedades tienen, sin saber nada de Flutter. Por eso cada componente reutiliza el schema del catálogo básico (BasicComponents.textField.schema): el contrato con el servidor no cambia, solo cómo se dibuja en tu app.

Agrega los paquetes de A2UI

En viajaria_app:

flutter pub add a2ui_core a2ui_flutter json_schema_builder

lib/a2ui_inputs.dart

import 'package:a2ui_core/a2ui_core.dart';
import 'package:a2ui_flutter/a2ui_flutter.dart';
import 'package:a2ui_flutter/basic_catalog.dart';
import 'package:material_ui/material_ui.dart';

// Cada componente usa el MISMO nombre y schema que el del catálogo básico:
// el contrato con el servidor no cambia, solo cómo se dibuja.
// props.writable('value')?.set(...) escribe lo que edita el usuario en el
// modelo de datos (null si la propiedad no está enlazada a una ruta).

final textField = ComponentImplementation(
  name: 'TextField',
  schema: BasicComponents.textField.schema,
  builder: (context, node, props, buildChild) => TextFormField(
    initialValue: props.string('value'),
    decoration: InputDecoration(
      labelText: props.string('label'),
      hintText: props.string('placeholder'),
    ),
    onChanged: (text) => props.writable('value')?.set(text),
  ),
);

final checkBox = ComponentImplementation(
  name: 'CheckBox',
  schema: BasicComponents.checkBox.schema,
  builder: (context, node, props, buildChild) => CheckboxListTile(
    title: Text(props.string('label') ?? ''),
    value: props.boolean('value') ?? false,
    onChanged: (checked) => props.writable('value')?.set(checked ?? false),
  ),
);

final slider = ComponentImplementation(
  name: 'Slider',
  schema: BasicComponents.slider.schema,
  builder: (context, node, props, buildChild) {
    final min = props.number('min') ?? 0;
    final max = props.number('max') ?? 100;
    final value = (props.number('value') ?? min).clamp(min, max);
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        Text('${props.string('label') ?? ''}: ${value.round()}'),
        Slider(
          value: value,
          min: min,
          max: max,
          onChanged: (v) => props.writable('value')?.set(v),
        ),
      ],
    );
  },
);

final choicePicker = ComponentImplementation(
  name: 'ChoicePicker',
  schema: BasicComponents.choicePicker.schema,
  builder: (context, node, props, buildChild) {
    final selected = switch (props.value('value')) {
      final List<Object?> values => values.whereType<String>().toList(),
      final String value => [value],
      _ => <String>[],
    };
    final multiple = props.string('variant') == 'multipleSelection';
    return Wrap(
      spacing: 8,
      children: [
        for (final option in props.list('options').whereType<Map>())
          ChoiceChip(
            label: Text('${option['label'] ?? option['value']}'),
            selected: selected.contains(option['value']),
            onSelected: (on) {
              final value = '${option['value']}';
              final next = !multiple
                  ? [value]
                  : on
                  ? [...selected, value]
                  : selected.where((v) => v != value).toList();
              props.writable('value')?.set(next);
            },
          ),
      ],
    );
  },
);

final dateTimeInput = ComponentImplementation(
  name: 'DateTimeInput',
  schema: BasicComponents.dateTimeInput.schema,
  builder: (context, node, props, buildChild) => ListTile(
    leading: const Icon(Icons.event),
    title: Text(props.string('label') ?? 'Fecha'),
    subtitle: Text(props.string('value') ?? 'Elige una fecha'),
    onTap: () async {
      final picked = await showDatePicker(
        context: context,
        firstDate: DateTime.now(),
        lastDate: DateTime(DateTime.now().year + 2),
      );
      if (picked == null) return;
      // Formato de fecha de A2UI: AAAA-MM-DD.
      props.writable('value')?.set(picked.toIso8601String().substring(0, 10));
    },
  ),
);

final setComponents = {
  'TextField',
  'CheckBox',
  'Slider',
  'ChoicePicker',
  'DateTimeInput',
};

/// El catálogo básico de A2UI 1.0 (mismo id que el del servidor), con los
/// componentes de entrada dibujados con material_ui.
final basicMaterialUiComponents = [
  for (final c in BasicComponents.all)
    if (!const setComponents.contains(c.name))
      c,
  textField,
  checkBox,
  slider,
  choicePicker,
  dateTimeInput,
];

final basicMaterialUiCatalog = CatalogImplementation(
  id: BasicCatalog.v1_0Id,
  protocolVersion: A2uiProtocolVersion.v1_0,
  components: basicMaterialUiComponents,
  functions: BasicCatalog.v1_0().functions.values.toList(),

El modelo escribe la interfaz en A2UI Express, una notación compacta que gasta menos tokens que JSON. El middleware a2ui() la valida y la convierte en mensajes JSON (A2UI 1.0), que viajan en el mismo stream del agente.

Experimental. genkit_a2ui está marcado como experimental y los paquetes de A2UI están en versión 0.x: su API cambia entre versiones. Fija las versiones en tu pubspec.yaml.

a2ui() hace tres cosas en cada llamada al modelo: le inyecta al prompt qué componentes puede usar (Text, Card, Column, Button...), extrae los bloques <a2ui> que el modelo escribe en Express, y los reemplaza por partes de datos (application/a2ui+json) con los mensajes JSON. Tu agente no cambia: solo le agregaste un middleware en use.

Reinicia el servidor (dart run bin/server.dart).

validate acepta 'warn' (el valor por defecto: avisa en el log y descarta el bloque), 'strict' (lanza un error) y 'off'. Si un bloque no compila, a2ui() le pide una vez al modelo que lo corrija (repair, activo por defecto). Mientras desarrollas, a2ui(validate: 'strict', repair: false) te deja ver rápido los errores del modelo.

Crea lib/viajaria_ui.dart. La función a2uiMessagesFrom saca los mensajes JSON de las partes A2UI de cada chunk, y un MessageProcessor los aplica. Cada superficie que crea el modelo se dibuja con A2uiSurface:

import 'dart:async';

import 'package:a2ui_core/a2ui_core.dart';
import 'package:a2ui_flutter/a2ui_flutter.dart';
import 'package:genkit/client.dart';
import 'package:genkit/experimental_client.dart';
import 'package:material_ui/material_ui.dart';

import 'a2ui_inputs.dart';
import 'main.dart' show baseUrl;

/// El tipo de las partes A2UI que manda el servidor.
const a2uiMimeType = 'application/a2ui+json';

/// Los mensajes A2UI (JSON) que vienen en las partes de un chunk.
Iterable<Map<String, dynamic>> a2uiMessagesFrom(List<Part>? parts) sync* {
  for (final part in parts ?? const <Part>[]) {
    if (part.metadata?['mimeType'] != a2uiMimeType) continue;
    if (part.data?['messages'] case final List messages) {
      yield* messages.whereType<Map>().map((m) => m.cast<String, dynamic>());
    }
  }
}

sealed class _Entry {
  const _Entry();
}

class _TextEntry extends _Entry {
  _TextEntry(this.isUser, this.text);

  final bool isUser;
  String text;
}

class _SurfaceEntry extends _Entry {
  const _SurfaceEntry(this.surface);

  final SurfaceModel<ComponentImplementation> surface;
}

class ViajarIAUiChat extends StatefulWidget {
  const ViajarIAUiChat({super.key});

  @override
  State<ViajarIAUiChat> createState() => _ViajarIAUiChatState();
}

class _ViajarIAUiChatState extends State<ViajarIAUiChat> {
  late final _agent = remoteAgent(url: '$baseUrl/api/viajaria-ui');
  late final _chat = _agent.chat();

  // El renderer: aplica los mensajes A2UI y guarda las superficies.
  late final _processor = MessageProcessor<ComponentImplementation>(
    // el catálogo básico 1.0 (el mismo del servidor) con los componentes de material_ui
    catalogs: [basicMaterialUiCatalog],
    defaultVersion: A2uiProtocolVersion.v1_0,
    validationConfig: ValidationConfig.relaxed,
    outboundListener: _onOutbound,
    unifiedOutbound: true,
  );

  final _controller = TextEditingController();
  final _entries = <_Entry>[];

  bool _busy = false;

  @override
  void initState() {
    super.initState();

    // Cada superficie nueva se vuelve una entrada más del chat.
    _processor.model.onSurfaceCreated.subscribe(
      (surface) => setState(() => _entries.add(_SurfaceEntry(surface))),
    );

    // El servidor borra una superficie antes de volver a dibujarla.
    _processor.model.onSurfaceDeleted.subscribe(
      (id) => setState(() {
        _entries.removeWhere((e) => e is _SurfaceEntry && e.surface.id == id);
      }),
    );
  }

  @override
  void dispose() {
    _processor.dispose();
    _agent.close();

    _controller.dispose();
    super.dispose();
  }

  Future<void> _send() async {
    final text = _controller.text.trim();
    if (text.isEmpty || _busy) return;

    _controller.clear();
    setState(() => _entries.add(_TextEntry(true, text)));
    await _runTurn(_chat.sendStream(text: text));
  }

  // Un botón de la superficie se manda al agente como el siguiente turno.
  void _onOutbound(RendererToAgentMessage message) {
    if (message is! ActionMessage || _busy) return;
    setState(() => _entries.add(_TextEntry(true, '▶ ${message.action.name}')));

    final payload = Message(
      role: Role.user,
      content: [
        DataPart(
          data: RendererToAgentMessagePayload([message]).toJson(),
          metadata: {'mimeType': a2uiMimeType},
        ),
      ],
    );
    unawaited(_runTurn(_chat.sendStream(message: payload)));
  }

  Future<void> _runTurn(AgentTurn turn) async {
    setState(() => _busy = true);
    _TextEntry? prose;

    try {
      await for (final chunk in turn.stream) {
        // 1) El texto normal va al chat.
        if (chunk.text.isNotEmpty) {
          if (prose == null) {
            prose = _TextEntry(false, '');
            _entries.add(prose);
          }
          setState(() => prose!.text += chunk.text);
        }

        // 2) Los mensajes A2UI van al renderer.
        for (final message in a2uiMessagesFrom(chunk.raw.modelChunk?.content)) {
          try {
            _processor.processMessages(message);
          } on A2uiError catch (e) {
            debugPrint('No se pudo aplicar el mensaje A2UI: ${e.message}');
          }
        }
      }

      await turn.response;
    } catch (e) {
      setState(() => _entries.add(_TextEntry(false, 'Error: $e')));
    } finally {
      if (mounted) setState(() => _busy = false);
    }
  }

  @override
  Widget build(BuildContext context) => Scaffold(
    appBar: AppBar(title: const Text('ViajarIA (UI)')),
    body: Column(
      children: [
        Expanded(
          child: ListView.builder(
            padding: const EdgeInsets.all(12),
            itemCount: _entries.length,
            itemBuilder: (context, i) => switch (_entries[i]) {
              _TextEntry(:final isUser, :final text) => Align(
                alignment: isUser
                    ? Alignment.centerRight
                    : Alignment.centerLeft,
                child: Padding(
                  padding: const EdgeInsets.symmetric(vertical: 4),
                  child: Text(text),
                ),
              ),
              // La superficie A2UI que armó el modelo.
              _SurfaceEntry(:final surface) => A2uiSurface(
                key: ObjectKey(surface),
                surface: surface,
              ),
            },
          ),
        ),
        if (_busy) const LinearProgressIndicator(),
        Padding(
          padding: const EdgeInsets.all(8),
          child: TextField(
            controller: _controller,
            enabled: !_busy,
            decoration: const InputDecoration(
              hintText: 'Pide destinos, una lista, un formulario...',
            ),
            onSubmitted: (_) => _send(),
          ),
        ),
      ],
    ),
  );
}

Qué pasó: el modelo escribió un bloque Express, a2ui() lo validó y lo convirtió en mensajes JSON dentro del stream, a2uiMessagesFrom los sacó del chunk, MessageProcessor los aplicó y A2uiSurface los dibujó. Al pulsar un botón, el outboundListener recibe la acción y la app la manda como {"messages": [...]}, el mismo formato JSON.

Trata lo que emite el modelo como entrada no confiable. La validación revisa la estructura y los tipos de los componentes, no sus valores: un modelo con prompt injection puede emitir una Image.url cualquiera. Quien renderiza (tu catálogo en la app) debe sanitizar las props, y en web conviene una Content Security Policy que limite img-src. Tampoco metas datos secretos en el modelo de datos: pueden volver en el context de una acción.

El catálogo básico incluye una función openUrl para botones que abren un enlace en el navegador. Esta app no la registra (no le pasa un callback a basicCatalog()), así que si el modelo genera un botón de ese tipo, no hará nada. Es a propósito: la URL la elige el modelo, y abrirla sin control sería otro punto de entrada para un prompt injection.

Middleware propio: protege las imágenes

validate: 'strict' solo revisa la estructura de los componentes, no sus valores. El catálogo básico sigue incluyendo Image, y un modelo con prompt injection puede pedir una imagen de cualquier URL. La recomendación del propio paquete es agregar tu propio middleware que revise los mensajes JSON que emite a2ui().

Un middleware de modelo envuelve la llamada al modelo: recibe la petición, llama a next(...) y puede cambiar lo que vuelve. El nuestro tiene una sola regla: si una Image apunta a un host que no está en la lista permitida, la cambia por un Text.

En bin/server.dart agrega la clase (fuera de main). GenerateMiddleware, ModelResponse y Part vienen de package:genkit/genkit.dart, que ya importaste:

class ImageHostGuard extends GenerateMiddleware {
  ImageHostGuard(this.allowedHosts);

  final Set<String> allowedHosts;

  @override
  Future<ModelResponse> model(
    ModelRequest request,
    ActionFnArg<ModelResponseChunk, ModelRequest, void> ctx,
    Future<ModelResponse> Function(
      ModelRequest request,
      ActionFnArg<ModelResponseChunk, ModelRequest, void> ctx,
    )
    next,
  ) async {
    // 1) Lo que va por el stream: revisa cada chunk antes de enviarlo.
    final guardedCtx = ctx.streamingRequested
        ? ctx.copyWith(
            sendChunk: (chunk) => ctx.sendChunk(
              ModelResponseChunk(
                role: chunk.role,
                index: chunk.index,
                content: chunk.content.map(_guard).toList(),
                custom: chunk.custom,
                aggregated: chunk.aggregated,
              ),
            ),
          )
        : ctx;

    final response = await next(request, guardedCtx);

    // 2) El mensaje final (el que se guarda en el historial).
    final message = response.message;
    if (message == null) return response;

    return ModelResponse(
      message: Message(
        role: message.role,
        content: message.content.map(_guard).toList(),
        metadata: message.metadata,
      ),
      finishReason: response.finishReason,
      finishMessage: response.finishMessage,
      latencyMs: response.latencyMs,
      usage: response.usage,
      custom: response.custom,
      raw: response.raw,
      request: response.request,
      operation: response.operation,
    );
  }

  /// Si la parte es A2UI, cambia las imágenes de hosts no permitidos por texto.
  Part _guard(Part part) {
    if (!isA2uiPart(part)) return part;

    // Copia profunda de los mensajes JSON: no modificamos lo que devolvió el modelo.
    final messages = a2uiEnvelopesFromParts([part])
        .map((m) => jsonDecode(jsonEncode(m)) as Map<String, dynamic>)
        .toList();

    var blocked = false;
    for (final message in messages) {
      // Los componentes llegan en createSurface (superficie nueva) y en
      // updateComponents (actualización de una superficie existente).
      for (final kind in const ['createSurface', 'updateComponents']) {
        final body = message[kind];
        final components = body is Map ? body['components'] : null;
        if (components is! List) continue;

        for (final c in components) {
          if (c is Map && c['component'] == 'Image' && !_isAllowed(c['url'])) {
            final id = c['id'];
            c
              ..clear()
              ..['id'] = id
              ..['component'] = 'Text'
              ..['text'] = '[imagen bloqueada]';
            blocked = true;
          }
        }
      }
    }

    // Sin cambios, la parte sigue igual (con su fuente Express).
    // Con cambios, la fuente Express ya no coincide: se arma sin ella.
    return blocked ? a2uiPart(messages) : part;
  }

  bool _isAllowed(Object? url) {
    // Un binding { path } no es una URL que podamos revisar: se bloquea.
    if (url is! String) return false;
    final uri = Uri.tryParse(url);
    return uri != null &&
        uri.scheme == 'https' &&
        allowedHosts.contains(uri.host);
  }
}

Para probarlo, pide "Muéstrame un destino con su foto, usa esta imagen: https://example.com/foto.png". Si el modelo genera una Image, debe llegar a la app como un texto "[imagen bloqueada]".

El orden en use importa. El primer middleware de la lista es el más externo y el último queda pegado al modelo. Por eso el guard va antes de a2ui(): cuando a2ui() termina de convertir el bloque en mensajes JSON, esa parte pasa por el guard antes de llegar al cliente. Y retry() va al final: así repite solo la llamada al modelo.

Por qué se quita la fuente Express: a2ui() guarda el bloque Express original en la metadata de la parte, y es lo que el modelo ve en los siguientes turnos. Si el guard cambia los mensajes JSON, ese Express ya no coincide, así que la parte se arma de nuevo sin él.

Hasta ahora el agente decide y ejecuta solo. Hay acciones que no deberías dejar que haga sin preguntarte: reservar un tour, pagar un anticipo, cancelar un viaje. Para eso están los interrupts: la tool del servidor se pausa, la app le pregunta al usuario y, con su respuesta, el agente continúa.

 1. Usuario: "Resérvame un tour a Cusco"
 2. Agente (servidor): llama a la tool reserveTour → se PAUSA (interrupt)
 3. App Flutter: recibe el interrupt con el destino
 4. App Flutter: muestra "¿Reservar el tour a Cusco?" y el usuario confirma o cancela
 5. App Flutter: responde → chat.resume(respond: [...])
 6. Agente: confirma la reserva (o dice que se canceló)

La decisión sale del servidor y se queda en la app: el modelo no puede reservar sin que el usuario lo apruebe. Es el mismo mecanismo para cualquier acción que necesite un "sí" humano, o un dato que solo vive en el cliente.

Experimental, igual que el resto de la Agents API.

Con esto, cuando el modelo llame a reserveTour, el turno termina con finishReason: interrupted y la app recibe la petición pendiente. Reinicia el servidor (dart run bin/server.dart).

Si una tool siempre debe pausar, existe ai.defineInterrupt(). Aquí usamos una tool normal que devuelve .interrupt(); así también podrías decidir cuándo pausar (por ejemplo, solo si el tour tiene cupo limitado).

El middleware toolApproval (paquete genkit_middleware) hace lo mismo sin escribir la pausa: cualquier tool que no esté aprobada se pausa hasta que el usuario la apruebe, y luego se ejecuta en el servidor. Revisa genkit_middleware en pub.dev.

App: pregunta al usuario y reanuda

En viajaria_app crea lib/viajaria_reservas.dart:

import 'package:genkit/experimental_client.dart'; // remoteAgent (browser-safe)
import 'package:genkit/genkit.dart';
import 'package:material_ui/material_ui.dart';

import 'main.dart' show baseUrl;

class ViajarIAReservas extends StatefulWidget {
  const ViajarIAReservas({super.key});

  @override
  State<ViajarIAReservas> createState() => _ViajarIAReservasState();
}

class _ViajarIAReservasState extends State<ViajarIAReservas> {
  late final _agent = remoteAgent(url: '$baseUrl/api/viajaria-reservas');
  late final _chat = _agent.chat();

  final _controller = TextEditingController();
  final _reservas = <String>[]; // las reservas viven en la app

  String _answer = '';
  bool _busy = false;

  @override
  void dispose() {
    _agent.close();
    _controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => Scaffold(
    appBar: AppBar(title: const Text('ViajarIA (reservas)')),
    body: Padding(
      padding: const EdgeInsets.all(16),
      child: Column(
        children: [
          Expanded(child: SingleChildScrollView(child: Text(_answer))),
          if (_reservas.isNotEmpty) ...[
            const Divider(),
            Text('Mis reservas: ${_reservas.join(', ')}'),
          ],
          TextField(
            controller: _controller,
            enabled: !_busy,
            decoration: const InputDecoration(
              hintText: 'Pide reservar un tour',
            ),
            onSubmitted: (_) => _send(),
          ),
        ],
      ),
    ),
  );

  Future<bool> _confirm(String title) async {
    final ok = await showDialog<bool>(
      context: context,
      builder: (context) => AlertDialog(
        title: const Text('¿Reservar este tour?'),
        content: Text(title),
        actions: [
          TextButton(
            onPressed: () => Navigator.pop(context, false),
            child: const Text('Cancelar'),
          ),
          FilledButton(
            onPressed: () => Navigator.pop(context, true),
            child: const Text('Reservar'),
          ),
        ],
      ),
    );
    return ok ?? false;
  }

  Future<void> _send() async {
    final text = _controller.text.trim();
    if (text.isEmpty || _busy) return;
    _controller.clear();

    setState(() {
      _busy = true;
      _answer = '';
    });

    try {
      final turn = _chat.sendStream(text: text);
      await for (final chunk in turn.stream) {
        setState(() => _answer += chunk.text);
      }
      var res = await turn.response;

      // Mientras el agente esté pausado, resuelve cada interrupt y reanuda.
      while (res.finishReason == FinishReason.interrupted) {
        final parts = <ToolResponsePart>[];

        for (final interrupt in res.interrupts) {
          if (interrupt.name == 'reserveTour') {
            final args = interrupt.input as Map<String, dynamic>;
            final destination = args['destination'] as String;

            final confirmed = await _confirm(destination);
            if (confirmed) setState(() => _reservas.add(destination));

            parts.add(
              interrupt.respond({
                'confirmed': confirmed,
                'destination': destination,
              }),
            );
          }
        }

        res = await _chat.resume(respond: parts);
      }

      setState(() => _answer = res.text); // respuesta final del agente
    } catch (e) {
      setState(() => _answer = 'Error: $e');
    } finally {
      if (mounted) setState(() => _busy = false);
    }
  }
}

Ejecuta la app (con el servidor corriendo) y escribe: "Resérvame un tour a Cusco". Debe aparecer el diálogo; si confirmas, el agente responde que quedó reservado y el destino aparece en "Mis reservas". Si cancelas, debe decir que no se hizo.

Qué pasó: el turno terminó "a medias" con finishReason: interrupted. La app tomó la petición, preguntó al usuario y reanudó el mismo turno con chat.resume. El modelo nunca vio un "sí" que el usuario no dio.

El runtime valida que cada respond coincida con una pausa activa (por nombre y por ID de referencia). No puedes inventar resultados desde el cliente para una tool que no pausó.

La reserva aquí es solo en la app (una lista en memoria) para mantener el ejemplo simple. En una app real, el respond sería el resultado de llamar a tu backend con el usuario autenticado.

Lo que construiste está pensado para desarrollo. Antes de desplegarlo, revisa al menos esto:

  • CORS: CorsOptions() vacío permite todos los orígenes. Restringe con CorsOptions(allowedOrigins: ['https://tuapp.dev']).
  • Autenticación: pasa un contextProvider a cada addAgent y manda el token desde Flutter con headers en remoteAgent. Aplica a todas las rutas del agente (turno, getSnapshot y abort).
  • Store compartido: InMemorySessionStore se pierde al reiniciar y no sirve con varias instancias.
  • Archivos del servidor: la carpeta prompts/ y el viajaria-catalog.json se leen desde disco, así que tienen que viajar con tu servidor.
  • API key: guárdala en un gestor de secretos, no en texto plano.
